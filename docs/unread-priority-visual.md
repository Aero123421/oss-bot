# 未読優先度の視覚仕様（案B）

目的：注意を「全部の新着」ではなく **要判断** に運ぶ。コスト方針どおり、全員オンライン同期や過剰バッジは避ける。

## 優先度（高い順）

| 級 | 種別 | 例 | 視覚（ラベル） |
|----|------|-----|----------------|
| P0 | 要判断 | 承認 pending、再認証、doctor_failed、自分宛の決定依頼 | `◆` ＋「要判断」テキスト。色は警告系（具体HEXは実装トークンへ委譲） |
| P1 | 自分宛 | @メンション、Dispatcherからの振り分け | `●` 強（通常より濃い／太字） |
| P2 | 通常新着 | ルーム／DMの未読メッセージ | `●` 弱 |
| P3 | 実行気配 | Botが実行中 | ヘッダの薄い「実行中」のみ。サイドバーを赤くしない |
| — | 既読／無新着 | — | バッジなし |

## 置き場所

- **サイドバー行**：P0–P2 のみ。P3はヘッダ在席に限定（コスト：薄い在席）
- **要対応リスト**：P0必須、P1任意。P2は入れない（トリアージ汚染防止）
- **ストリーム**：未読アンカーは任意。本流をバッジで埋めない

## Dispatcher窓口

- 参謀（窓口）DMに P0 が付いたときは、他DMより上にソート固定を維持したままバッジを出す
- 「司令塔の未読ダッシュボード」は作らない

## やらないこと

- 全Bot常時オンライン点灯
- 既読・タイピングのフル同期表示
- 未読＝ログ件数の生表示

## 受け入れ

- [ ] P0 が P2 より視覚的に強い
- [ ] 要対応に P2 通常新着が流れ込まない
- [ ] 実行中はヘッダ気配に留まる
- [ ] 秘密やトークンは未読UIに出ない
