# 承認カード状態ルール（案B直後）

目的：重い操作をAdminに逃がさず、**ストリーム／要対応**でトリアージする。

## 対象操作（例）

- コネクタ接続・再認証
- 破壊的／課金／外部送信の可能性がある一手
- ルーチンの新規作成・権限変更
- コンピュータ上の確認が必要な操作

## 状態

| 状態 | 意味 | UI | サイドバー／要対応 |
|------|------|-----|-------------------|
| `pending` | 人の判断待ち | カード表示、[許可][拒否][後で] | 要対応に上げる（優先高） |
| `allowed` | 許可済み・実行中／完了待ち | カードは折りたたみ要約へ | 要対応から外す（または完了へ） |
| `denied` | 拒否 | 「拒否済み」＋理由任意 | 要対応から外す |
| `deferred` | 後で | カードは残すが弱く表示 | 要対応に残す（優先中） |
| `expired` | タイムアウト | 「期限切れ・再依頼可」 | 要対応に残すかアーカイブ |

## 配置

1. **発生源のストリームにインライン**（どの会話で求められたか分かる）
2. 同時に **要対応** にエントリ（未読の主役）
3. モーダル全画面や設定画面専用フローにしない（詳細設定が必要ならカード内の「詳細」で第2層へ）

## コピー指針

- 何をするか／なぜ必要か／拒否したらどうなるか、を1画面で
- 技術トークンをそのまま出さない
- 1カード＝1判断（複数権限のバンドル禁止）

## 受け入れ

- [ ] pending がストリームと要対応の両方に出る
- [ ] allowed/denied 後に要対応が片付く
- [ ] Adminだけの承認画面が初回パスに出ない
