# 承認カード状態ルール（案B直後）

目的：重い操作をAdminに逃がさず、**ストリーム／要対応**でトリアージする。BYO再認証・doctor失敗も含む。

## 対象操作（例）

- コネクタ接続・**再認証**
- 破壊的／課金／外部送信の可能性がある一手
- ルーチンの新規作成・権限変更
- コンピュータ上の確認が必要な操作
- **doctor 赤**（到達阻害・ランタイム失敗）の修復確認
- BYO CLI／APIキーの Setup（未ログイン → Ready）

## 状態

| 状態 | 意味 | UI | サイドバー／要対応 |
|------|------|-----|-------------------|
| `pending` | 人の判断待ち | [許可][拒否][後で] または [再認証][後で] | 要対応◆（優先高） |
| `allowed` | 許可済み・実行中／完了待ち | 折りたたみ要約 | 要対応から外す |
| `denied` | 拒否 | 「拒否済み」＋理由任意 | 外す |
| `deferred` | 後で | 弱表示で残す | 要対応に残す（中） |
| `expired` | タイムアウト | 「期限切れ・再依頼可」 | 残すかアーカイブ |
| `reauth_required` | BYO／コネクタ失効 | [再認証] 主CTA。秘密入力はマスク／OS側 | ◆要判断 |
| `doctor_failed` | doctor 赤 | 何が赤か＋直す1コマンド／[doctorを開く] | ◆要判断 |

## 配置

1. **発生源のストリームにインライン**
2. 同時に **要対応**（未読の主役は通常●より◆）
3. モーダル全画面や設定専用フローにしない（詳細はカード内「詳細」→第2層）
4. **秘密の生値はカードに出さない**（状態と次の一手だけ）

## コピー指針

- 何をするか／なぜ必要か／拒否・後回ししたらどうなるか
- doctor失敗は「ログを読め」ではなく「直す1手」
- 1カード＝1判断（権限バンドル禁止）

## 受け入れ

- [ ] pending / reauth_required / doctor_failed がストリームと要対応に出る
- [ ] allowed/denied 後に要対応が片付く
- [ ] Adminだけの承認画面が初回パスに出ない
- [ ] 再認証・doctor導線でトークン生値を表示しない
